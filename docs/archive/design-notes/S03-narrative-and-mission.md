# S03：两段叙事、人物关系与任务接口

设计日期：2026-10-13。依据：0.6.1 实际脚本、[总计划](production_plan.md)、[S02 资源去向](S02-resource-plan.md)。本步交付可供后续制作的故事与接口设计；文中新增镜头、演出控制和存档扩展均待实现，不代表已有可播放开场。实际步骤状态见 [PROGRESS.md](../PROGRESS.md)。

## 1. 本步确定的故事

先以山河、乡土、雪地行军和战斗群像介绍东北抗联，再把视角收进两名战友的一次休整。沈砚与姜岚在艺术化天池高地短暂交谈，对太平生活的牵挂成为后续救人的情感起点。离开高地后用行军蒙太奇压缩数日旅程，在青岚林场入口获得最新敌情：交通员陆山受伤被扣，搜山名册也在电报房。姜岚守住回山方向，由沈砚进入林场取名册、断电话中继、救人，经北侧通道到渡口掩护解缆撤离。

宏大序章表现长期斗争，具体任务落在“带回一个人，保护名册背后的乡亲”。天池承担地域意象和战友相处的场地，不承担整座可玩关卡的地理定位，也不替代现有电报房与渡口任务。

确定采用 **两名既有角色的天池谈话**，不新增班长角色，不让陆山提前以健康队友身份出现。S05 根据本稿写原创台词；《使命召唤14》只提供战友相处、交代任务、危机升级和玩家接管的节奏参考。

## 2. 时间、地域与信息揭示

| 段落 | 时间／地域表达 | 观众此时知道什么 |
|---|---|---|
| A1–A6 历史序章 | 跨季节的历史主题蒙太奇，不是任务当天连续录像 | 为什么战斗、环境何以艰苦、战士守护的家园与人；雪地和深秋可以分镜表现 |
| B1–B3 天池岩台 | 画面标注“数日前 · 长白山天池高地（艺术化场景）” | 沈砚与姜岚同行；下一站去林区接头、接应交通员陆山，搜山形势趋紧 |
| B4 行军与转场 | 背起装备、离开岩台，山路／林道片段，明确时间省略 | 这是一段经过压缩的旅程，不能用一次连续摇镜暗示林场就在湖边 |
| B5–B6 林场外围 | “1938 年深秋 · 东南满林区 · 青岚林场（虚构）” | 姜岚先行侦察后带回林师傅的消息；昨夜送信的陆山受伤被扣，名册危及密营和接济乡亲 |
| 正式可玩任务 | 沿用既有深秋林场场景 | 以实际交互逐步确认人物处境与路线，最终把人和名单一同带回 |

B3 只讲原定接头与接应安排，不提前宣布陆山已经被扣数日；B5 才揭示最新消息。这与林守义现有“昨晚捎话、今天未能走出电报房”的叙述相容。姜岚在转场期间先行摸清情况的事实由 B5 动作／对白交代，不新增需要玩家游玩的侦察支线。

天池高地是原创虚构人物的一段艺术化前序。不得把 A4 的复用地图交火标成真实天池战役，不标注未经考证的精确行军里程、真实部队番号或战役日期。人物谈话的近景岩台、到达和离开方向在 S20–S22 另建。

## 4. 第一段：历史宏大叙事

暂定 75–90 秒，以 S04 旁白节奏和后续实录调整。用户指定原文作为唯一正式旁白输入，完整保留：

> 作为中国共产党创建最早、坚持抗日时间最长、条件最为艰苦的抗日武装力量，东北抗日联军在民族危亡之际，高擎抗日救国大旗，在白山黑水间、在冰天雪地里、在茫茫林海中，孤悬敌后，进行了艰苦卓绝的斗争。忠诚于党的坚定信念、勇赴国难的民族大义、血战到底的英雄气概，这是战火磨练铸成的东北抗联精神，也是中华民族在每次危难之际迸发的复兴强音

## 5. 第二段：原创任务序幕

暂定 60–90 秒。本表确定信息与动作意图，S05 写最终对白，S06 决定逐镜时长和拍摄方式。

| 段号 | 剧情与人物动作 | 必须交付给观众的信息 | 状态边界 |
|---|---|---|---|
| B1 岩台休整 | 沈砚看湖／整理腕袖；姜岚站在侧前方，转头回应视线 | 两人短暂停留，面对开阔山河，处境艰苦但并未失去生活愿望 | 只有演出角色；不开枪、不消耗正式装备 |
| B2 战友闲谈 | 谈家乡和太平以后再来看湖，留出听话、停顿和目光反应 | 战友关系来自相处；台词原创、朴素，不再次朗诵历史口号 | 对话由演出控制，不弹出当前选择式对话框 |
| B3 原定行程 | 姜岚指向离开方向，沈砚检查携行装备 | 下一站去林区，与青岚林场一线的林师傅接头、接应陆山；搜山形势使联络更紧迫 | 还不知道“昨夜被扣”的新变化；不发名册、不救人、不领取补给 |
| B4 数日行军 | 起步、山脊／林道片段、遮挡切换；说明姜岚先行侦察后会合 | 时间已经过去，地点转到虚构林场；地图之间通过剪辑连接 | 不建立天池到林场的长距离可玩道路，不将高地坐标写进现有存档 |
| B5 最新敌情 | 林口会合，姜岚说清名册、伤员、总闸和渡口；岗哨动静使两人压低身体 | “人和名册都要带回”；先到木棚问林师傅，再突破检查口；取册后断中继，接陆山经北侧撤离 | 远声／岗哨动作属于演出压力，不抢先触发正式守卫伤害、追兵或任务计时 |
| B6 行动交接 | 姜岚留守回山方向；最后镜头对齐沈砚起点和视线，HUD 与手中步枪平稳出现 | 玩家独自进入当前路线；可向林师傅求助，姜岚仍可补问路线 | 正常看完与跳过 B 都进入同一可玩起点；见下方交接契约 |

B5 必须涵盖全部必要任务信息；B6 接管时用短提示保留“木棚补给、J 看记录”。不强制玩家再问一次姜岚才能开门。若跳过 B，任务记录仍包含完整目标，补问姜岚只显示现有后续路线说明。

下表是本轮读源码确认的既有行为，不是新实现。详细函数位置、摘录和哈希见 [源码核对证据](narrative/S03/source_audit.json)。

| 接口 | 当前行为 | 新开场必须遵守的条件 |
|---|---|---|
| `mission.start_new()` | 立即重置任务、玩家、角色、守卫；保存并进入 `playing`；提示先找姜岚 | 接入时需拆开“准备新任务”和“保存／开放控制”，不能直接调用后让战斗在过场下继续运行 |

| 初次接敌 | `met_scout` 为真且玩家 X > 24，`contact_started` 才置真 | 接管在 X=10，不自动激活第一岗哨；B5 的声响不调用正式接敌逻辑 |
| 守卫与追兵 | 5 名初始、4 名追兵、最多存活 6；分区激活；断电且渡口门开启后才推进追兵 | A4/B5 不调用正式生成与击杀逻辑；看完／跳过不能重复生成敌人 |
| 陆山救援 | 包扎可选；跟随／等候可选；未处理速度 2.2、处理后 3.2 | 开场不预先招募或包扎，保留玩家资源选择；不要把“已接应”与“已治疗”合并 |

| 继续检查点 | 恢复玩家、角色、任务、敌人、路线；没有 `linear` 的旧档关闭新路线约束 | 继续游戏不能统一重置到 B6；老档仍按原有兼容方式恢复 |

## 7. 计划中的过场进入／退出契约

下述名称是后续实现约定，当前工程尚无开场控制器。结构化交接值见 [接口契约](narrative/S03/interface_contract.json)。

```mermaid
flowchart LR
  Menu[开始任务] --> A[A1–A6 历史序章]
  A -->|完成或跳过第一段| B[B1–B6 任务序幕]
  B -->|完成或跳过第二段| H[统一提交交接状态]
  H --> Play[检查口 → 木料巷 → 电报房 → 渡口]
  Save[继续有效游戏检查点] --> Play
  OpeningSave[继续过场检查点] -->|按保存段落从头播放| AorB[A1 或 B1]
```

**进入新任务：** 准备一份合法的新任务状态，只执行一次重置与初始守卫准备；进入历史序章模式时关闭玩家输入、正式 AI、伤害交互与任务计时。演出使用角色和场景副本或隔离的演出层；初始任务快照里的正式角色仍在林场锚点。A 完成／跳过转 B，不改变任务进度。B 完成／跳过共同进入单一交接入口。

**交接结果：** `stage=0`，任务耗时 0，击杀 0，已击败集合为空；`met_scout=true`（保存为 `briefed=true`），补给选择 `none`、未读家书、未取医药包、未招募陆山、门未打开，绷带 1；陆山位于既有伤员锚点且不跟随、未治疗。路线启用、三门未开、尚未接敌、未开始解缆、剩余 12 秒。5 名初始守卫保留，尚无追兵。玩家回到 `START=(10,0.08,86)`、朝向 Y=-0.6、俯仰 0、生命 100、步枪选中，弹匣 `[5,10]`、备弹 `[35,50]`；第一人称相机 FOV 78、相对高度 1.57，见当前恢复函数。

**交接顺序：** 在控制仍关闭时校准人物、相机、武器及任务状态 → 清理演出字幕／声音／副本 → 写入同一份可恢复的游戏检查点 → 开放控制并显示目标。若写入失败，不宣称已保存；显示实际错误并保留内存状态，允许重试保存或回到菜单。S34 实现和验收错误处理。重复收到完成／跳过事件只能成功交接一次，不能再次恢复满血、加弹药、重置击杀或重复生成守卫。

结束镜头应在相机仍由演出控制时收敛到玩家相机，再开放鼠标，避免画面和持枪位置跳变。所有按住的开火、瞄准、装填与移动请求在交接边界清理；完成／跳过按钮的输入消费掉，避免落到游戏后变成一次射击。B 段枪声和 A4 交火不能消耗上述弹药。

**暂停：** A/B 各有独立暂停上下文；Esc 弹出演出暂停菜单，恢复仍回原段原播放位置。镜头、动画、粒子和声音同步暂停；设置界面返回同一暂停上下文。不能直接复用现有 `resume()`，因为它无条件进入 `playing`。当前 HUD 对未知模式仍尝试取首个菜单按钮，新模式必须同时接入菜单分支，不能只增加一个字符串。

**跳过：** 分别提供“跳过历史序章”和“跳过任务序幕”；跳过 A 进入 B，跳过 B 进入上述统一状态。进入 B 时不自动把整个开场算作已完成。恢复和跳过后停止上一段声音与字幕，正式短对白只在 `playing` 运行。

## 8. 存档、重试与中断设计

继续使用现有游戏存档 version 2 与现有 `story`、`linear`、`encounter` 数据，**计划新增可选顶层 `opening` 字段**，内部 version 1、phase 为 `history`／`task`／`gameplay`。它只是拟定接口，不是当前已支持的字段。读档时必须新增校验与分流，不依赖当前读取器对额外字段的忽略行为。

过场保存到“段落边界”：开始 A 保存 `history`；进入 B 保存 `task`；交接保存 `gameplay`。从中途退出／断电恢复，A 从 A1 重放、B 从 B1 重放，不承诺逐帧恢复。过场期间存储的是合法林场初始状态，不能把天池镜头或演出人物的位置塞进目前仅允许林场边界的玩家／陆山坐标。

| 情况 | 计划结果与不变量 | 实现／验收步骤 |
|---|---|---|
| 正常看完 A、B | 交接一次，进入同一林场起点，任务已说明、资源未被演出消耗 | S07 原型，S25/S33 正式接管 |
| 跳过 A，观看 B | 从 B1 开始；最终状态与完整观看一致 | S07/S34 |
| 观看 A，跳过 B | 直接提交统一状态；J 可查任务，不要求重复完成首次简报 | S25/S34 |
| 连续跳过两段／连点跳过 | 仍只重置一次、交接一次；资源与敌人数不增加 | S34 |
| A 或 B 暂停、进设置、返回 | 时间、声音、动画不继续；返回原段，不能误入 `playing` | S07/S34 |
| A 中途退出或中断 | 有效 `history` 检查点从 A1 恢复 | S34 |
| B 中途退出或中断 | 有效 `task` 检查点从 B1 恢复，不重复 A | S34 |
| 交接完成后立刻退出 | `gameplay` 检查点直接恢复游戏，不重新播放 A/B | S34 |
| 战斗失败后“返回检查点” | 按真实任务快照恢复敌人、资源与伤员；不返回片头 | S34 |
| “重新开始”／胜利后“再试一次” | 作为新任务从 A 开始，用户可分别跳过；不继承旧击杀与路线 | S34 |
| 老档无 `opening`，有 `linear` | 直接恢复既有游戏状态；不得默认补成 `briefed=true` | S34 |
| 更早老档无 `opening`、无 `linear` | 保留既有路线约束关闭、三门通行与必要位置纠正；不补新的解缆要求 | S34 |
| `opening` 值损坏／未知版本或与任务状态冲突 | 报告无效记录并保留文件，给出重开入口；不静默改成已完成开场 | S34 |
| 演出加载或保存失败 | 保留最近成功检查点与错误证据；不把失败算作开场／步骤完成 | S07/S34 |

拟新增 `opening` 的 `history/task` 仅接受未交接的新任务状态（`stage=0`、未简报、未招募、无击杀、无打开栅门和追兵）；`gameplay` 接受当前合法游戏快照。无字段老档视为“沿用旧游戏流程”，不因全局看过开场标记去改任务。制作时验证磁盘写入和读档路径；本步只确定契约，未执行上述运行测试。
