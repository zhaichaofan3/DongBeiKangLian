# 《林海归途》接近《使命召唤7》整体质感的单关卡评估

日期：2026-10-12。状态：评估与建议，未执行引擎迁移或替换当前运行包。

后续更新：用户已指定《战地1：钢铁风暴》视频为最终视觉与叙事参考，见 [新标准及原创关卡方案](bf1_reference_direction.md)。本文件保留当时对 COD7 和 0.3 的检查证据；资源现已收集，见 [资源库](../AssetLibrary/README.md)，其中三项录音已接入并更新发布包。

用户已选择：**保留东北抗联原创故事，对标整体质感**。这里的目标是第一人称观感、动作可信度、环境完整度与叙事节奏；关卡、人物、任务仍属于《烽火回声》。

## 1. 可行性结论

**在受控规模内，制作接近这一代商业 FPS 表现的原创单关卡有可行路线。现有 0.3 能复用玩法，但美术资产和动作制作需要升级。**

| 目标 | 判断 | 前提 |
|---|---|---|
| 60–90 秒可玩的质量样板：精细双手、步枪、林场小场景、一段交火 | 最适合先做，可验证 | 有合适的连续拓扑模型、可靠绑定和专门的动作制作 |
| 8–12 分钟东北抗联原创关卡，双枪、三名友方、数段战斗 | 条件可行，工作量主要在内容 | 先通过样板，再扩展资产、NPC 动作、布景、音效与关卡事件 |
| 整关每个镜头、人物表演、配音、动作数量都与原作商业成品无差别 | 当前无法保证 | 需要显著更多美术、动画、声音和反复试玩投入 |

现有 117 项自动检查只证明玩法与动作状态运转正确，不能证明手掌造型、皮肤变形、动画节奏或画面达到了目标。旧版固定视角的高 FPS 也不能直接推算新资产、新渲染效果和真实交火的性能。

## 3. 当前原型为什么显得粗糙

对照 `weapon_visuals.gd`、`fps_player.gd`、`human_model.gd` 及已有实际截图：

| 问题 | 当前实现 | 需要的升级 |
|---|---|---|
| 手像球串与圆柱 | 椭球手掌、圆柱手指和球关节，合并成刚体网格 | 连续皮肤拓扑、正确掌形/指缝/拇指、关节环线、法线细节 |
| 握枪与装填僵硬 | 手、腕、袖子整体平移旋转，指形不变 | 肩肘腕与完整手指骨骼、蒙皮权重、抓握/释放姿态 |
| 手像在追赶零件 | 手、枪机和弹夹按不同时间公式运动 | 在同一动作中制作接触关系，保持抓住的部件与手指同步 |
| 近景材质单薄 | 无皮肤专用纹理；金属/布料 64²、木纹 128² 程序纹理 | 匹配 UV 的颜色、法线、粗糙度、金属度贴图，合理磨损与布料细节 |
| 动作缺少重量 | 位移插值与正弦运动占主导 | 专门的关键帧、预备动作、受力、停顿、回收、受限惯性叠加 |
| 枪械操作有简化 | 驳壳枪可见弹夹为 7 发而容量为 10；剩余弹量共用动作 | 先选定具体历史武器，统一模型、容量、装填动作与弹药提交规则 |
| 瞄准构图粗 | 固定偏移和 FOV 插值，缺少资产校准流程 | 建立照门/准星锚点，匹配弹道中心与视线，检查枪机遮挡 |
| NPC 和场景风格不一致 | 分段刚体人物、规则墙体与平地、重复材质 | 蒙皮人物、可信步态与接触；重做地形、建筑比例、材质分层与布景 |
| 声音缺乏层次 | 程序合成枪声和简化环境音 | 机械声、枪口声、尾音、抛壳、布料、脚步和空间声学一起制作 |

## 4. 技术路线：保留玩法，建立美术资产流程

推荐 **Godot 4.7.2 + Blender + GLB 资产管线**。本轮在 PATH 和常见安装位置没有找到 Blender，开始制作样板时需要安装并验证导出流程。

现有移动、命中、任务、对话、护送、存档可以继续使用。第一人称表现拆成独立场景，由玩法事件驱动，逐步替换程序网格：

```text
Gameplay：移动 / 射击 / 弹药 / 任务 / 存档
    ↓ 发出动作请求；验证弹药提交与取消
WeaponView：动作状态 / 优先级 / 中断与恢复
    ├─ 专用双手袖子 Skeleton3D + 蒙皮网格
    ├─ 近景枪械及枪机、弹夹等活动部件
    ├─ AnimationPlayer 保存导入动作
    ├─ AnimationTree 控制过渡与混合
    └─ 抓握、瞄准、枪口、抛壳和声音事件锚点
```

枪械关键动作与手臂在同一套参考坐标下制作并同步导出。IK 用于少量接触校正；换弹接触和手指表演以专门制作的动画为主。呼吸、移动惯性、轻微后坐作为受限叠加层，防止再次把所有运动堆在一个根节点上。

玩法层负责射击是否合法、弹药是否提交；动画提供可校验的时点。切枪、装填中断、死亡、读档、暂停恢复都要明确，防止动画结束时重复补弹。

Blender 制作使用米制、统一轴向/骨骼命名/原点；留存可编辑源文件，导出 GLB。导入后检查法线、贴图色彩空间、缩放、蒙皮、动画根运动和动作事件。以固定镜头的展示场景验证，不把自动导入成功当作美术完成。

### 渲染器选择

手指形状和蒙皮首先取决于资产。Compatibility 也可以做好专用双手和动画。场景样板再单独比较 Forward+：它可提供体积雾、屏幕空间反射等效果，同时带来性能和着色器适配成本。

建议优先使用合理曝光、方向光、接触阴影、室内烘焙与局部灯光、基础雾和统一调色；按需要增加体积雾。避免靠过量雾、泛光和强烈镜头摇晃掩盖资产问题。切换渲染器必须重验现有水面/树叶着色器和全关表现。

| 选择 | 本项目的收益与代价 | 建议 |
|---|---|---|
| 现有 Godot + 骨骼资产；样板比较 Forward+ | 可复用已经验证的玩法，重点投入内容制作 | 当前优先路线 |
| 迁移 Unreal Engine 5 | 有丰富美术/动画工具与素材生态，但需重做导入、角色、AI、UI、存档和测试；美术工作仍存在 | 只有具体资产或工具优势足以抵消迁移成本时再评估 |

## 5. 单关卡建议

保持 1938 年深秋、青岚林场、名册与救援主线。目标仍为 8–12 分钟首次体验，使用几个紧凑、连通的区域，先以两场主要交火控制规模。

| 段落 | 玩家经历 | 本段需要体现的质量 |
|---|---|---|
| 林道接头 | 蹲行接近侦察员，低声交谈，观察巡逻 | 双手近景、湿地/落叶、树冠层次、队友视线与手势、林风 |
| 林工棚—运材场 | 询问情况，穿过木料和铁路设施，第一次交火 | 清楚的路线、可信掩体、敌人探身/受击、枪械音画反馈 |
| 电报房 | 开门、取回名册、断电、找到伤员 | 手接触门/物品，室内外明暗过渡，纸张、木材和金属细节 |
| 伤员撤离 | 扶起或包扎陆山，带他通过追兵区域 | 成对互动动画、伤员步态、对话触发与跟随节奏 |
| 林溪渡口 | 同伴到位，掩护收束，进入结尾 | 木船和水岸关系、环境声音、简短角色表演和收尾节奏 |

可以通过近处对白、字幕、动作和少量脚本事件增强叙事；保留原有可选择的交谈，不要求制作长时间电影过场。敌人先做巡逻、警戒、使用少数掩体点、射击与受击，不在本轮扩大成大规模战场系统。

## 6. 按验收件推进

### A. 先锁定参考与一把具体武器

确定本关步枪的具体型号、弹容量和装填方式；收集能够看到真实手部动作的实机/操作参考。原作现代武器可参考动作的节奏与镜头组织，不能直接套到栓动步枪。参考清单分别标明观感参考、历史参考、可用于工程的资产及其来源。

### B. 先交付第一人称质量样板

范围：一套双手与袖子、一把步枪、约 20×30 米可移动测试场景，形成 60–90 秒的展示/交火流程。所需内容：

- 连续拓扑、绑定、蒙皮的手臂源文件与 GLB；精细近景枪模与简化世界模型。
- 颜色/法线/粗糙度/金属度等适当贴图；2K 作为近景纹理起点，按屏幕占比和显存调整，不追求所有物品 4K。
- 约 12–18 个动作片段/姿态：待机、移动、冲刺进/循环/出、举/收枪、瞄准进/出、射击、拉栓、装填和必要中断分支。具体数量以选定枪械为准。
- 枪机、弹夹、手指、弹壳、机械音、枪声与镜头反馈同步。

验收看正常播放与慢放：手指不呈球串状；腕部无明显断裂或塌陷；抓握后接触点稳定；无明显穿枪/悬空操作；瞄准基准与弹道一致；插弹和闭锁有明确受力及节奏；连续输入和中断后弹药正确。拍摄相同照明/角度的前后对比片段。

### C. 制作一小段环境和一个 NPC 样板

用林道或电报房验证地形、树、建筑、道具、光照和声音的一致性。NPC 采用蒙皮角色，先完成待机、行走、转向、举枪、射击、受击以及一种短互动；检验脚滑、穿地、转身和距离变化。对话人物与敌人可共享基础骨架，但动作/衣着需适配。

质量稳定后再确定正式渲染器与预算。不要先把现有整张地图堆满高精度资产，再处理风格和性能不匹配。

### D. 扩展成完整关卡

增加第二把枪及对应动作、三名友方外观与关键互动、敌人动作，扩展林场模块。建议初始资产范围：一套林区环境、约 20–35 个建筑/结构模块、约 25–40 个常用道具变体、少量重点近景物件、2–3 种树与若干地表植物；这是规划数量，可通过模块复用收缩。

声音至少覆盖枪械机械声、射击空间尾音、室内外脚步、衣料、环境循环和关键交互。对白可先用临时配音验证节奏，最终声音来源单独确认。所有新增资产登记来源和可用范围。

### E. 真实通关验收

在实际跑动、室内外交火、队友同时活动、粒子和声音开启时记录帧时间与显存；检查关卡首次运行、重新进入、读档和动作中断。最后安排真人首次游玩，测量路线理解、交火节奏与真实通关时长。

## 7. 本机条件与预算目标

本轮读取到：AMD Ryzen 7 H 260（8 核/16 线程）、约 31.3 GiB 系统内存、RTX 5060 Laptop（8151 MiB 显存），C 盘约 207 GiB 空闲。

这套设备适合作为本项目的开发与验证机器。拟定目标为 **1080p、完整交火下稳定 60 FPS**。建议初始工作预算为实际 GPU 占用约 5–6 GiB 内，给驱动/桌面留余量；按实测调整贴图、阴影、雾与视距。它们是目标，不是已经达成的承诺，也不构成其他机器的最低配置结论。

角色和武器细节按近景价值分配，远景用简化模型与 LOD；树木/道具复用实例化；限制同时活动敌人数与投影灯数量。正式性能验收采用真实流程的长时间采样，包含平均帧时、尾部帧时和卡顿位置。

## 8. 时间、成本与自主制作边界

目前没有选定可用的手臂骨骼、枪械资产或动作库，不能可靠承诺整关日历工期。现阶段最有意义的预算单位是“通过验收的一套手臂与武器动作组合”和“一段完整环境”，先完成样板再用实际速度估计其余部分。

零购买预算可以优先寻找许可明确的免费基础网格、扫描材质和环境资产，再自行改造；主要代价是匹配风格、补拓扑、重绑权重和修动作的时间。成熟付费资产可能减少准备工作，但在具体资源与适配成本明确前不能认定一定更省时。

我可以持续承担制作管线、脚本、资产接入、可自动化的模型处理、状态机、音画事件、测试和打包，也可以迭代美术与动作。但“所有模型与表演纯程序从零生成，并保证整关达到商业原作一致质量”目前没有可靠依据。高质量基础资源与逐动作目视修整是关键依赖；样板未过关时，应集中修正，不能把功能测试通过等同于美术验收。

**推荐下一项：制作一把步枪和一套真正蒙皮双手的质量样板，同时确定环境的材质/照明风格。样板通过后，再扩展为整关规模。**
