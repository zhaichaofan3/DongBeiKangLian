# S09 开工与贯通验收入口

S08为设计交付，下一次获准执行S09时使用。当前没有执行本清单中的游戏改造。

## 输入与顺序

1. 读根进度，核对S08已完成；按自动开关领取后保存S09开工project检查点。读 [S08主记录](../../S08-route-and-pacing.md)、[路线数据](route_plan.json)、[调查折线](source_survey.json) 与 [S03接口约定](../../S03-narrative-and-mission.md)。
2. 在正式工程内为D01–D09建立可开关的简化体块与清楚编号。D07是D05内的子槽；不要重复堆一个屋顶。外围D01只作景观，主边界不开放；先用简单尺寸校准，S10/S11再接真实资源。
3. 保留起点、任务物、三门、伤员和追兵入口。保留现有碰撞基线，查清与新体块相交的旧树、箱体、地面细节，只移动确实冲突的布景并记录前后。禁止靠打开所有门来冒充正常贯通。
4. 以玩家身高查主路2.4米、伤员转弯3米、门4米的设计留空；检查高障碍和屋檐是否挡枪线。矩形间距通过不代替这一检查。原场景处于窄口时先记录原因再局部修正，不为方便扩大所有通道。
5. 核对D03仓库、D04厂房和D05生产棚在主要方向可见；不改变建筑取舍以制造文旅地标。D05水轮暂不运行，保持无水渠时的合理性。
6. 真实走通“开始任务含开场→接管→检查口→木料巷→电报房→原门返回→北侧→渡口”。分别补查直接进入林场和跳过两段后接管；这三种入口不会变更任务条件。
7. 完成本步下列必要验证，记录实际时间与玩法限制；保存project检查点和证据。不要在S09同时宣称完成S10精美建筑、S13全部AI路线优化或S35性能优化。

## 必须观察／验证

| 场景 | 验收内容 |
|---|---|
| 新任务完整闭环 | 有碰撞的新体块下，正常关门状态开局；按既有条件开两门、取册、断电、招募、开渡口门、解缆、对话撤离；最终won |
| 主路与可选路径 | 可绕访林守义也可跳过；木料巷医药包、门旁缺弹兜底仍可达；不靠新增必做对话解锁 |
| 救援顺序 | 先招募后取册／断电与先完成任务物再招募都可达；包扎不是通关门槛 |
| 伤员路线 | 未治疗与已治疗两种速度，从西门返回并绕北侧；不得传送或穿墙“修复”卡住；允许玩家正常等待 |
| 门口与交互 | 名册2.3米、总闸2.3米、人物约2.8米和栅门3.3米范围可用；交互方向不被装饰截住 |
| 渡口与追兵 | 初始5人、追兵4人、最大同时6人；固定入口与延后生成仍有效，守卫/陆山不被新布景卡住 |
| 解缆 | 累计12秒；离开、暂停、让陆山等候停止且保留计时；满足最终距离和互动条件后可撤离，不要求杀光追兵 |
| 存读档与基线回归 | 前后门状态、物资、伤员、追兵与解缆恢复；S07暂停／跳过／按段恢复无新增回归。完整异常矩阵仍留S34 |
| 节奏记录 | 记录自动流程实际用时与路线，标明测试控制方法；真人未试玩就不宣称已达到8–12分钟 |
| 画面证据 | 每区一张可见粗体块和道路的图片，另留西门折返、北侧护送、渡口南向追兵视线；明确标为简化结构 |
